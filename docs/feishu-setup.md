# 飞书接入配置（给 Grok Bot 写入 / n8n 拉取）

n8n **主动轮询**飞书多维表格，每 5 分钟一次。全程是出站请求，**不需要放行任何公网端口**。

```
Grok Bot ──写入──→ 飞书多维表格 ──每5分钟拉取──→ n8n → Postgres
                        ↑                              │
                        └────── 回写「已接收」+ 选题ID ───┘
```

## 一、建飞书自建应用

1. 打开 https://open.feishu.cn/app → **创建企业自建应用**
2. 「凭证与基础信息」页 → 复制 **App ID** 和 **App Secret**
3. 「权限管理」→ 勾选：
   - `bitable:app`（查看、评论、编辑和管理多维表格）
   - 或只要读+写：`bitable:app:readonly` + `bitable:app`
4. 「版本管理与发布」→ **创建版本 → 申请发布 → 管理员审核通过**
   ⚠️ 不发布版本，权限不生效，API 会返回无权限

## 二、建多维表格

新建一个多维表格，按下表建列（列名必须完全一致，n8n 按中文列名取值）：

| 列名 | 类型 | 必填 | 说明 |
|---|---|---|---|
| 标题 | 文本 | ✅ | 选题标题，空则跳过 |
| 角度 | 文本 | 推荐 | 切入角度，决定文章走向 |
| 方向 | 文本 | | 如 AI工具 / AI行业 |
| 关键词 | 文本 | | 逗号分隔 |
| 选题理由 | 多行文本 | | 为什么值得写 |
| 来源 | 文本 | | `grok_x` / `workbuddy`，默认 feishu |
| 原文链接1 | **文本**（别用 URL 类型） | ✅ | 真实可点击链接 |
| 原文正文1 | 多行文本 | ✅ | **原文全文**，服务器抓不了海外站点，没有正文就写不了稿 |
| 原文标题1 | 文本 | | |
| 原文链接2 / 原文正文2 / 原文标题2 | 文本 | | 可选，最多支持 3 条 |
| 状态 | 单选：待处理 / 已接收 / 已废弃 | | n8n 回写，新行**留空即可** |
| 选题ID | 文本 | | n8n 回写 |

**状态逻辑**：空 或 `待处理` → 会被拉取；`已接收`/`已废弃`/`生成中`/`已完成` → 跳过。

## 三、把应用加为表格协作者（最容易漏的一步）

多维表格右上角 `···` → **添加文档协作者** → 搜索你刚建的应用名 → 加为**可编辑**成员。

不做这步，n8n 拉记录会报无权限。

## 四、取 app_token 和 table_id

打开表格，URL 长这样：

```
https://xxx.feishu.cn/base/BascnXXXXXXXX?table=tblYYYYYYYY&view=vewZZZZ
         ↑                      ↑
      app_token = BascnXXXXXXXX     table_id = tblYYYYYYYY
```

## 五、填进服务器 .env

```bash
ssh root@175.178.120.171 "cat >> /opt/n8n/.env <<'EOF'
FEISHU_APP_ID=cli_xxxxxxxx
FEISHU_APP_SECRET=xxxxxxxx
FEISHU_APP_TOKEN=BascnXXXXXXXX
FEISHU_TABLE_ID=tblYYYYYYYY
EOF"
```

（若已存在同名键，用 `vi /opt/n8n/.env` 改值，别重复追加）

## 六、部署并自检

```bash
ssh root@175.178.120.171 "bash /opt/n8n/create_wf1b.sh"
```

脚本会：写入 settings 表 → **直接调飞书 API 自检**（能取到 token、能读到记录才继续）→ 导入并激活工作流。

自检通过后会打印前 3 条记录的 JSON，能看到 `fields` 里有没有「标题」「原文链接1」这些列。

## 七、给 Grok Bot 的写入要求

告诉它往这张表写记录，必须包含：

- `标题`
- `原文链接1`（真实链接，不要编造）
- `原文正文1`（**抓下来的原文全文，不要摘要、不要改写**）
- `状态` **留空**（不要写"待处理"以外的乱值，否则可能不被拉取）

## 已知限制

- 每次最多拉 50 条；正文很长的行建议一次别铺太多
- 5 分钟一轮，够用；想更快改工作流里 Schedule 节点的间隔
- 飞书 API 有频率限制，当前用量远低于阈值
